> 本更新包**自成一体**：鸿蒙团队只看这份 + U03 即可。🔴 **一级 bug，优先于手上其他卡**

## 一句话

U03 定的备份包格式没错，是 **iOS 的导出漏写了心情**：2026-10-17 到 10-28 之间 iOS 导出的备份包，每篇日记都没有 `moodValence`、`moodLabels`，导回去心情全没了（日记上的心情标记、写作统计里的心情一起消失）。**鸿蒙照 iOS 源码快照写导出的话，很可能同样漏了 —— 请按本包自查。**

## 发生了什么

- U03 给 `entries.json` 每篇加了两个可选字段 `moodValence`（number）、`moodLabels`（string 数组），导入照着读 —— **这两条 iOS 导入一直是对的**
- 但 iOS 导出拼每一篇时**没传这两个字段**，它们按默认值空着写出去（JSON 里直接没有这两个键）。编译不报错、导出不报错、包也能导入，只是心情没了，所以一直没发现
- 2026-10-28 用户自己导出十几篇再导回去发现的

## 影响范围

| 情况 | 结果 |
|---|---|
| 2026-10-17 前 iOS 导出的包 | 那时还没有心情这两个字段，本来就没有 —— 不受影响 |
| **2026-10-17 – 10-28 iOS 导出的包** | **没有心情，也补不回来**（包里就没写）。导入后这些日记都是「没记心情」 |
| 2026-10-28 起 iOS 导出的包 | 带心情（iOS 提交见下） |
| 鸿蒙导出的包 | 看鸿蒙自己的导出写没写 —— 按下面自查 |

导入规则**不变**（U03 / R-DATA-01）：按 id 跳过已有、不覆盖。所以已经导入过的「没有心情」的日记，再导一次修好的包也不会补上心情；本机原来就有、没删过的日记不受影响。

## 鸿蒙要做的

**R-BACKUP-MOOD-01**（补充 U03「备份包变化」，规则本身不变）：导出 `entries.json` 时，**每一篇记了心情的日记都要写出 `moodValence` 和 `moodLabels`**；没记心情的那篇这两个键可以不写或写 null。导入照 U03：`moodValence` 夹到 -1…1，`moodLabels` 原样收（不认识的 key 留着，显示时跳过）。

**验收（新增，以后每次动备份包都要跑）：往返测试** —— 造几篇日记，心情覆盖最低、偏低、正中、偏高、最高五档，各带一个情绪词，再加一篇没记心情的 → 导出 → 导入到一个**空的**库 → 逐篇比对：id 一样、`moodValence` 一样、`moodLabels` 一样，没记心情的那篇仍是空。

## iOS 这边（只是告知，鸿蒙不用照做）

- 导出补上这两个字段（`Services/Backup/BackupExporter.swift` 的 `makeBackupEntry`）

- 模拟器上跑过往返测试：五档 + 一篇没记心情，导出 → 导入空库，全部对上
