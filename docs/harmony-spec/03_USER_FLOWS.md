# 03 · 关键用户流程

> 端到端的「用户做了 X，系统做了 Y」流程。鸿蒙端按这些流程实现，**行为必须跟 iOS 一致**，但 UI 可重新设计。

---

## 流程 1 · 首次打开 App

```
0. 🔴 隐私协议同意页（盖在最上层，不同意过不去）—— 比较 acceptedLegalVersion 与当前协议版本号
     · 同意前不发任何网络请求、不申请任何权限（R-APP-01~03）
1. App 启动 → 检测是否走完引导（Preferences key: hasCompletedOnboarding）
2. 没走完 → 进入 OnboardingPage（一页）
     ├─ 「选择你的纸张」：素笺 / 皮革 / 肯特（三套全部免费）
     ├─ 「给笔友起个名字」：输入框，占位"青鸟"，可跳过（空 = 青鸟）
     └─ 「开始书写」按钮
3. 完成 → 存主题、存笔友名、hasCompletedOnboarding=true，进主 Tab
4. 主 Tab 出现时：补齐 12 个预设心情；日记本表为空则建「生活 / 读书笔记 / 旅行 / 工作」
   **不铺示例日记**（R-APP-07），新用户看到的是空的记录页
5. 后续启动 → 直接进主 Tab
```

**Onboarding 不要求登录** — 用户可以匿名记日记。**只在寄信 / 订阅 / 账户操作时才提示登录**（lazy login）。

## 流程 2 · 写日记并保存

```
1. 入口：记录页列表模式底部浮钮「写下今天的故事」/ 大屏模式导航栏「+」/ 日记本主页「写一篇」（带入那本）
2. ComposePage（全屏）：
   - 自动获取当前日期（不可改）+ 字数
   - 此时此地（天气 + 地点，可换、可不记）
   - 标题输入框（可空，≤ 40 字）
   - 正文区（图文混排，可插照片 + 录音）
   - 心情选择器（横滑卡片）
   - 「收进日记本」（单选，可当场新建；不选 = 只在「全部日记」）—— 2026-10 起
3. 右上 ✓ = 「完成了一篇书写」→ 这一刻才产生一篇正式日记（正文全空时 ✓ 不可点）
4. 左上返回：
   - 正文全空 → 直接退出
   - 有内容 → 弹「不保存 / 保存草稿」（点遮罩 = 回到编辑）
     · 保存草稿：存进草稿表（全局一份），提示「草稿已保存」，**不产生日记**
     · 不保存：整份草稿作废，连同它引用的照片录音
5. 下次进写日记页自动接着写草稿，顶部一行「接着上次没写完的」
6. 后续在「日记本」里看到：书架 → 点开那本 → 目录（从早到晚编号，按月分组）
```

**关键决策**（2026-08-08 起，旧版「一律自动保存」已作废）：
- **只有点 ✓ 才算一篇**；退出前一定有一次挽回的机会（存草稿）
- 标题 / 心情 / 日记本都可以空 —— 唯一必要的是「日期」（自动、不可改）
- 写日记**不调我们的后端**（天气 / 地点查询走平台服务，不经我们的服务器）
- 草稿、墨迹会干、图文编辑的完整规则见 `06_RULES.md` R-ENTRY / R-RICH / R-INK

## 流程 3 · 翻页阅读一本日记

```
1. 「日记本」/ 书架 → 点开一本 → 日记本主页（2026-10 起，见 CHANGELOG 2026-10-08）
   - 上：封面大图（照片铺满 / 布面铺满）+ 书名 + 副标题
   - 下：目录，**按阅读顺序（从早到晚）编号**，按月分组；可切宫格小样
   - 底部：「开始阅读」+ 写一篇
2. 点目录里某篇 → ReaderPage 从这篇开始；点「开始阅读」→ 从第 1 篇（最早的）开始
   - 每篇第一页：页眉（日期 + 标题 + 心情 + 日记本）与正文同页（2026-09 起不再单独占一页扉页）
   - 后续页：内容分页（按高度分页，类似实体书）
3. 左右滑动翻页，**往后翻越来越新**
4. 一篇翻完自动接下一篇；整本读完是结尾页
```

**鸿蒙端简化建议**：
- iOS 用 `UIPageViewController .pageCurl`（书本翻页动画）。鸿蒙没原生支持。
- 鸿蒙端用 `Swiper` 做平滑左右切换即可，**不强求 page curl 视觉**

## 流程 4 · 邮筒寄信、信箱收信 ⭐

这是 App 的核心情感价值，详细给。**2026-09-14 整体重新设计**，旧的「点按钮立刻出信」流程已废弃。

🔴 **核心设定：邮筒是寄信的（主动），信箱是收信的（被动）。**
用户寄出日记，笔友的回信要过几天才「寄到」。

```
1. 主 Tab「邮筒」/ PostBoxPage —— 上面一个邮筒插画（每个主题一张），下面一行状态，再下面一块固定高度的地方
   - 右上角「信箱」入口，有未读回信时带红点
   - 下面那块按情况放：一叠「这次寄出的日记」/ 邮戳 + 在路上 / 退回来的信（2026-10-11）
   - 🔴 下面那块**高度固定**，换内容时邮筒不变大变小（投信动画要对准投信口）
2. 要寄出哪些日记：**上次寄信之后新写的**（按日记的「创建时刻」判断，不按日记日期）
   - 上次寄信 = 写好的信和「写信中」的信里最晚的寄出时刻（退回来的不算）
   - 列成一叠：日期 + 标题（没标题用正文第一行，都没有写「无题」），**默认全勾，可以取消**
   - 🔴 **服务器只收到勾上的那几篇**；取消的这次寄完就不再出现（它早于这次寄信）
   - 退回来那封里的日记不在这叠里（等用户决定重寄还是不寄）
   - 一篇新的都没有 → 不寄，文案「上次寄信之后还没写新日记，先写点什么再寄吧」
   - 从没寄过 → 全部日记都算新的；保护上限：一次最多 14 篇（取最近的）
3. 一进页面先问 GET /me/rhythm：现在不能寄（这周 / 今天 / 这个月寄过了）就在状态行提前说明，
   点邮筒只轻轻一顿不寄；本机还有「写信中」的信时也先不收下一封
4. 邮筒本身是按钮。点一下 = 投信（约 3 秒，平滑曲线、不回弹）：
   那叠日记收拢成一页信纸 → 滑进信封 → 封舌合上 → 会员盖自己的火漆（印面 = 昵称首字）/ 免费是普通封口
   → 信封举到投信口推进去 → 投信口翻板落回去（闷响）→ 邮戳淡出
   - 同步震动 + 声音；投信动画放的时候再点：直接忽略
   - 减弱动态效果：没有动画，只一下闷响的震动
5. **投进去就算寄出，不用等 AI**。点下的那一刻本地就创建 Letter：
   - status = generating、正文空、relatedEntries = 勾上的日记
   - generatedAt = **寄出时刻**（点下邮筒那一刻）
   - deliveredAt = **到达时刻** = 寄出时刻 + [6 小时, 72 小时] 均匀随机 —— 是个未来时间
   - stationery 按此刻会员身份（会员 = sealed），fromCharacter = 此刻笔友名，toName = 此刻昵称
   - 界面上它就是「在路上」：邮戳（日期 + 日记里记的地点）+「在路上」
   - 动画放完才申请通知权限（仅首次会弹）
6. 后台寄信（本机负责，见下面「寄信队列」）：POST /letter（entries 只放勾上的）
   - 成功：正文填上、status = pending，预约到达时刻的本地通知（已授权才排）
   - 断网 / 超时：不算失败，过一会儿接着寄；App 被杀，下次回到前台接着寄
   - 服务端出错：1 分钟、5 分钟后重试，连续 3 次不成 → 退回
   - 内容审核没过 / 没登录 / 节奏拦截（先补领，补不到）→ 直接退回
   - 退回：status = failed、errorMessage = 原因；邮筒页显示退信卡片「重新寄出 / 不寄了」
7. 回信在路上：信箱里**看不见**
8. 到达时刻一过：
   - 信出现在信箱里，带未读点；邮筒页右上角信箱入口亮红点
   - 本地通知弹出「你有一封新的回信 / {笔友}的回信到了，去信箱看看吧」
   - 点通知 → 打开 App → 切到邮筒 tab → 直接进信箱
9. 用户点信进 LetterDetailPage：打开即已读
```

**🔴 两端必须一致的规则**：

| 规则 | 值 |
|---|---|
| 回信最快 / 最慢多久到 | 6 小时 / 72 小时，区间内均匀随机 |
| 一封信「已到达」 | 正文非空、status ∈ {pending, delivered, read}、且 deliveredAt（为空时用 generatedAt）≤ 此刻 |
| 一封信「在路上」 | 同上，但 deliveredAt > 此刻 |
| 一封信「未读」 | 已到达 且 status ≠ read |
| 寄出哪些日记 | 创建时刻晚于上次寄出时刻的日记，最多 14 篇，**只寄用户勾上的** |
| 一封信「写信中」 | status = generating 且正文空（投进邮筒、回信还没写好），算「在路上」，也算「上次寄信」 |
| 一封信「退回」 | status = failed、正文空、且归本机负责；不算「上次寄信」 |
| 能不能连续寄 | 能（服务端节奏允许时）。每封各自随机到达；本机还有写信中的信时先不收下一封 |

**寄信队列（2026-10-11）**：
- 只有**投信的那台设备**负责寄 —— 本机另记一份「哪些信归我寄」（不进同步数据），
  写信中的信经云同步到别的设备，那边不会再寄一次
- 🔴 **重发之前先补领**：发过请求的信（可能服务端已写好、回执丢了）重发前先 GET /letters，
  服务端有、本机没有、写信时刻 ≥ 这封的寄出时刻 − 5 分钟的，就是它的回信，直接填进去，不写第二封。
  被节奏拦下（429）时也先补领一次
- 退回后「重新寄出」= 回到写信中、重试次数清零；「不寄了」= 清空 relatedEntries、本机不再管它，
  记录本身留着（哪都不显示），那几篇日记回到「这次寄出的日记」里

**通知**：
- 不需要服务器推送 —— 寄出时到达时刻已知，本机预约即可
- 🔴 **未授权时预约的通知会被系统静默丢弃**（iOS 实测，鸿蒙侧请自行确认平台行为）。
  所以要先申请权限再预约
- App 每次回到前台，把所有在路上的信的通知**重新排一遍**（同一封信同一个标识，覆盖不重复）。
  兜住：后来才开通知权限、从另一台设备同步来的在路上的信、切换了语言

**开发加速**（仅 Debug 包）：设置 → 关于 → DEBUG「Fast letter delivery」，1 分钟 ≈ 1 天，
回信 15 秒 ~ 3 分钟到达。正式包里不存在。

**关键决策**：
- **有频率限制**：后端免费用户每月 4 封、订阅用户每天 1 封（`Backend/shared/src/rhythm.ts`），超出返回 429
- **letter 永久保留** —— 即使源日记删了，信仍在（status / body / fromCharacter 都已快照）
- **跨设备**：本地 Letter 经 iCloud 同步，另一台设备到点也会在信箱看到
  - ⚠️ **已知缺口（2026-09-14），鸿蒙开工前必须先找产品确认**：到达时刻**只存在客户端本地**，
    后端 `letters` 表没有这一列。**如果鸿蒙从后端 `GET /letters` 拉信，会在寄出的那一刻就看到回信**，
    「过几天才寄到」的设定直接失效。彻底统一需要后端给 `letters` 加一列到达时刻，并在列表接口里
    过滤掉未到达的信 —— iOS 侧暂未做

## 流程 5 · 登录

```
1. 触发场景：
   - 用户主动在「设置」账户卡点「登录 / 注册」
   - 邮筒页未登录时，状态行写「登录之后，{笔友}才能给你回信」
   - 用户购买订阅
2. LoginPage（v1）：
   - 手机号 + 短信验证码（今天就能用，iOS 同一套）
   - 华为账号：⛔ 等后端补 POST /auth/huawei（09_OPEN_QUESTIONS.md Q1），之后作为主选项
3. 手机号流程：
   a. 输入 11 位手机号 → POST /auth/send-code → 按返回的 retryAfter 倒计时
   b. 输入 6 位验证码 → POST /auth/verify-code → 返回 jwt + user（未注册自动建号）
   c. token + 用户快照存**安全存储**，回到原页
4. 华为账号流程（后端就绪后）：
   a. Account Kit 授权 → 拿到 idToken
   b. POST /auth/huawei { idToken } → jwt + user
   c. 账号上没有手机号 → 设置一级页账户卡亮红色警告，引导绑手机号（R-ACCOUNT-03）
```

**关键决策**：
- 🔴 **手机号是账号的必需项**（第三方身份不可用时，只有它能找回账号）
- 绑手机号可能「换账号」（`switchedAccount`），必须用返回的 token 覆盖本地（`02_BACKEND_API.md`）
- 不做邮箱登录、不做微信登录、不做密码

## 流程 6 · 订阅（尺素会员）

> 边界与价格以 `Memoir/Docs/MEMBERSHIP.md` 为准；规则见 `06_RULES.md` R-MEMBER。

```
1. 入口只有四处（不弹窗、不打断写作）：
   - 设置 → 账户下面一组「尺素会员」
   - 非会员读完一封信，信末一行小字「想让笔友每篇都回？了解尺素会员」
   - 相纸选择处点了会员款（挂小火漆）

   → 续费说明紧贴购买按钮下方 → 恢复购买 / 用户协议 / 隐私政策
   - 拿不到商品：「暂时无法连接」+ 禁用购买，不显示写死的价格
3. 购买成功：
   - 本机立刻按商店权益解锁界面上的会员能力（相纸、封面版式、火漆信）
   - 把购买凭据交给服务端（⛔ 华为验证接口还是占位，Q2）；笔友来信额度只认服务端
4. 到期：已经用上的保持原样，只是不能给新东西用（R-MEMBER-07）
```

## 流程 7 · 同步日记（云同步）

⛔ **方案未定**（`09_OPEN_QUESTIONS.md` Q3）。约束：

## 流程 8 · 错误展示

任何接口失败 / 本地异常 → 通过 ErrorPresenter 弹顶部 toast（不要弹 Dialog 打断用户）。

```typescript
// 任意地方
this.appEnvironment.errors.present({
    message: '请求过于频繁，请稍后再试',
    kind: 'error'
})
```

## 启动流程（鸿蒙 entry）

```
1. EntryAbility.onCreate
2. 打开本地库（RDB 版本迁移在这里跑）；读偏好：语言、主题（旧 id 归一）
3. 按主题设应用明暗（深色主题 → 深色，浅色 → 跟随系统）
4. 初始化 AppEnvironment（http / session / errors / 寄信服务），从安全存储读 token
5. 主界面开始构建；同时若当前主题有启动封面且开关打开 → 封面盖在主界面上，0.7s 后淡出
6. 隐私协议版本不对 → 同意页盖在最上层
7. hasCompletedOnboarding：false → 引导页；true → 主 Tab
8. 一次性迁移（各自的标记 key）
```

**每次回到前台**（iOS 的做法，鸿蒙照做）：
- 重排所有在路上的信的到达通知（R-NOTIFY-04）
- 处理寄信队列，前台期间每 30 秒一次（R-OUTBOX-02）
- 同名日记本合并（R-BOOK-17）
- 刷新会员权益并交给服务端
- （若做了换图标）把桌面图标对回「应该是哪个」

   ├─ httpClient: HttpClient

## 不要做的流程（MVP 排除）

- ❌ 注册流程（验证码登录即自动注册，无独立注册步骤）
- ❌ 忘记密码（手机号 / HUAWEI ID 都不要密码）
- ❌ 邮箱验证（鸿蒙端不用邮箱登录）
- ❌ 多账户切换（一个 App 实例一个账户）
- ❌ 用户头像（v1.x 再加）
- ❌ 关注其他用户 / 发现页（永远不做，产品不是社交）
