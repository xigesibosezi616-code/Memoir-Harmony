## 这是什么

尺素（Memoir）的鸿蒙版：克制、温柔的私密日记 App，AI 笔友定期回信。iOS 版是参考实现。
**行为与数据必须与 iOS 一致；界面可以按 HarmonyOS Design 重画。**

- 施工手册：`docs/harmony-spec/10_BUILD_MANUAL.md`（一步一会话，按卡片做）

- 数据模型：`docs/harmony-spec/05_DATA_MODEL.md`
- 阻塞与待决：`docs/harmony-spec/09_OPEN_QUESTIONS.md`
- iOS 源码（只读参考）：`reference/ios/`
- 进度：`PROGRESS.md`

**冲突时以谁为准**：iOS 源码 > `06_RULES.md` > 其余文档。发现冲突追加到 `09_OPEN_QUESTIONS.md`，不要自己挑一个。

## 语言

- 默认用**中文**回复；代码注释用中文；标识符用英文（PascalCase 类型、camelCase 函数），尽量和 iOS 同名，方便对照

## 技术栈

ArkTS + ArkUI（Stage 模型），API <填>，DevEco Studio <填>。
本地存储：RDB + Preferences；敏感信息（登录 token）放安全存储，不放 Preferences。

## 工作节奏（硬性）

- 按 `10_BUILD_MANUAL.md` 的卡片做，**一次只做一张卡**；卡片「不要」里的事不碰
- **每完成一处有意义的改动就编译一次**，通过再继续
- 纯逻辑（判定、计算、解析、合并）**必须有单元测试**
- 完成后回报：改 / 新增了哪些文件、编译是否通过、单测结果、卡片验收逐条的结果、哪些需要真机或产品确认
- **不要自由发挥**：需要扩大范围才能完成时，先停下来说明，等确认

## 破坏性改动：必须先停下来说明方案、等确认

- **任何会丢数据的操作**（删库、清表、删用户文件）—— 绝对红线
- 改 RDB 表结构 / 迁移（每次升版本都要**拿上一版的真实库跑一次升级**才算完）
- 改备份包格式（跨端契约，要和 iOS 同步并升 `formatVersion`）
- 跨 3 个以上文件的重构；改依赖注入结构；改状态管理方案

## 调试方法

- **先打日志定位，再动手修**，不靠猜。日志打**完整错误**（code + message），不要只打一句「失败了」
- 「界面看着对」≠「真写进去了」：碰数据的改动要直接查 RDB 核对落库
- 需要点很多下才能到的页面：加临时调试入口，**验完删干净并搜索确认**
- 时间相关的逻辑（墨迹 24 小时、回信 6~72 小时、本周 / 本月）：把「现在」做成可注入参数，单测里跑穿多天

## 架构约定

- 依赖容器 `AppEnvironment`（`errors` / `http` / `session` / 寄信服务…）用 `@Provide` 注入，**不要随手写全局单例**
- 用户可见的失败统一走 `errors`（顶部提示条），**不要静默吞掉**
- 全工程**只用一种**状态管理写法（<填：V1 或 V2>），不要混用
- 主题色、字体只从主题 token 取，页面里不写死色值

## 多语言（硬性）

七种：简体中文 / 繁體中文 / English / 日本語 / 한국어 / Français / Español。没有「跟随系统」。

- **用户能看见的文字一律走字符串资源**，七种齐全；译文**取自 iOS `Localizable.xcstrings`**（已转成资源，索引见 `strings_index.json`），**不要机翻**
- 带名字 / 数字的句子整句交给译文排，不在代码里拼
- 日期、数字格式跟 App 语言，不跟系统语言
- 切换语言当场生效，不重启、不丢导航栈
- 动了文字就跑一次漏翻检查脚本 <填：命令>，退出码必须是 0

## 红线（产品承诺，写进了隐私协议）

- 日记正文、标题、照片、录音、天气、地点**不上传我们的服务器**，也**不存进开发者侧的云数据库**
- 只有用户寄信时，**勾上的那几篇**日记的标题 / 正文 / 日期 / 心情发给服务器；照片和录音任何情况下都不发
- 没有真实的同步成功事件，**不许对用户说「已同步」「数据安全」**
- 不收集设备标识符、不投广告、不做跨应用跟踪

## 与 iOS 同步

- **每周看一次** `docs/harmony-spec/CHANGELOG.md` 顶部（iOS 侧的增量），🔴 条目要排进计划
